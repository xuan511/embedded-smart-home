# 从这里开始：一步一步完成毕设

这是“现在做什么、做到什么程度才能继续”的行动清单。详细安装和接线操作在 [14 章完整教程](BEGINNER_GUIDE.zh-CN.md)，完整信号表在 [HARDWARE](HARDWARE.md)。遇到错误停在当前关口，先保存错误文本，不靠继续接更多外设解决。

**当前先走纯软件路线，不要求现在提供板型、VID/PID 或供电信息。** 先阅读教程第 3～4 节，安装环境、检查固定 SDK、离线编译两块板，再运行可选主机测试。下面第 0 步的信息核对可以后置，等实际接线/烧录前再集中完成；未知期间不据此猜测电气连接。

**当前现实进度：代码、构建和主机测试已有记录；实物握手、LCD/触摸、真实传感器、灯/风扇、NVS 掉电、微信手机与连续运行仍全部 NOT RUN。** 既有 CI 不等于你手里的板子已经通过。准确结果见 [VALIDATION](VALIDATION.md)。

本项目的连接固定为：

```text
Korvo 原配 LCD/触摸/SD 保留
Korvo USB-A Host → CP2102/CP2102N USB-UART → STM32 PA9/PA10
STM32 PB6/PB7 → SHT3x-DIS、BH1750
STM32 PB0/PB1 → 驱动模块 → 灯、低压风扇
```

这里的“两板通过 USB 连接”**不是**把线插进未知 STM32 学习板的 USB 插座。只有选定的单口 CP210x、默认 `10C4:EA60`、3.3V TTL 路径已经实现。Korvo 的编译目标始终是 `esp32s31`，不改成 `esp32s3`。

## 先记住三条操作规则

1. 电脑代码块在 **PowerShell** 执行；`home ...`、`net ...` 在 **Korvo 串口 monitor 的 home> 提示符**下执行。
2. 串口操作逐条发，等待对应 ACK/result=0、`pending=0`；改阈值后还要等 `synced=1`。Queued 只代表入队，不能整块粘贴开关/模式命令。
3. 每个关口同时留下“操作、版本、实际结果、原始证据”。失败也保留；文中的应看到是预期，不是可直接抄入论文的实测值。

## 第 0 步：清点并确认关键硬件

**前置条件：** 暂不接负载，先读完整教程第 1～3 节。你已有 ST-Link 和一个 USB 转串口模块，但后者的芯片/电平仍需核实。

只集中确认这三组信息：

| 需要确认 | 怎么取得依据 | 未知时怎样继续 |
| --- | --- | --- |
| STM32 学习板型号/丝印、供电入口、可用排针、板载 LED GPIO/有效电平 | 该板厂家原理图/说明与实物丝印；MCU 手册不能证明第三方 PCB 接线 | 先做软件安装；不猜供电脚。LED 未确认时不能用默认 PC13 验收 LED |
| USB-UART 芯片、VID/PID、UART 电平、TXD/RXD/GND 顺序 | 按教程第 2.1 节在电脑设备管理器读取硬件 ID；查模块原理图或测电平 | 不是 CP210x 或信息不足就先不接 MCU；按已选模块要求准备匹配模块 |
| STM32/探针供电关系、灯/风扇及驱动模块规格 | 具体板/探针手册；负载电压/额定与启动电流；驱动的 3.3V 输入与保护 | 不把 VTref 当供电，不并接不同电源输出，不用 GPIO 直接供负载 |

**应得到：** 三组信息都有可核对的来源；缺什么明确写未知。外设还没买齐不妨碍环境安装、编译和通信阶段。

**保存或回传这份文字清单：**

```text
STM32 板型号/丝印：
STM32 原理图/说明来源：
供电入口与供电电压：
确认有的排针（PA9/10、PB6/7、PB0/1、SWD、3V3、GND）：
板载 LED GPIO/有效电平（可先写未知）：
ST-Link 型号与各针定义来源：
USB-UART 芯片型号：
USB 硬件 ID（VID/PID）：
UART 电平及其确认依据：
模块 TXD/RXD/GND 标号：
目前已备齐的传感器/驱动/灯/风扇与规格：
```

**进入下一步：** 软件环境可立即安装；实物供电/下载只能在对应板与探针接法确认后进行。

## 第 1 步：把电脑环境准备正确

**前置条件：** 普通 Windows 电脑、可访问官方依赖源，知道怎样打开 PowerShell 和切换目录。按完整教程第 4 节逐条操作，不混用别的项目的 SDK/PATH。

采用一套固定路线：

- ESP：固定 ESP-IDF `d35ea023029363d97c42565f85e0db23486f26b2`、BSP 1.0.1，按该提交官方 install/export 脚本安装/激活，完整获取递归子模块。
- STM32：Arm GNU 14.2.Rel1（gcc 显示 14.2.1）+ CMake + Ninja；烧录用 STM32CubeProgrammer + ST-Link。
- 仓库：clone 后切换 `codex/dual-board-usb-basics`，不要只使用旧 main。解压源码快照则按交付说明记录 manifest 中的 commit，不在没有 `.git` 的目录运行 `git log`。

在**已激活固定 ESP-IDF 的工程根目录**检查：

```powershell
Get-Location
git log -1 --oneline
python tools/check_environment.py
arm-none-eabi-gcc --version
cmake --version
ninja --version
```

源码快照不执行第二行，其他检查仍适用。安装/激活命令和每次重开终端的步骤见完整教程第 4 节；这里不重复整套安装。

**应看到：** 环境检查 `Baseline check PASS`，固定 SDK 提交、递归子模块 OK、RISC-V GCC 16.1.0；Arm/CMake/Ninja 均能输出版本。检查只证明环境一致。

**保存或回传：** 使用的工程路径、commit/manifest 版本、环境检查完整输出、三条版本命令输出。失败时保留第一条完整错误，不只写“编译不行”。

**进入下一步：** 所需命令可用，检查没有通过跳过子模块或修改 SDK 绕过。可以在未连接板子时先构建固件。

## 第 2 步：两块板分别编译、分别烧录

### 2A. Korvo：现在离线构建，后续再烧录

**当前编译的前置条件：** 固定环境已通过，不需要连接任何板子。**后续烧录的前置条件：** 核对硬件后只接 Korvo，保留原配 LCD/触摸，不接 CP210x 和外部负载。用数据线连接 UART Type-C 识别 COM 号；Power Type-C 只是供电，USB-A 留给 Host 通信。

首次在工程根目录：

```powershell
idf.py --preview set-target esp32s31
idf.py --preview build
```

现在只需等到 Project build complete，检查 `build/embedded_smart_home.bin` 和 `build/flasher_args.json` 存在。这一步是编译通过，还没有烧录。`set-target` 只在首次设置/纠正目标时运行，后续正常改代码或参数不要反复重置自己的配置。

进入实物阶段且确认 UART 端口后，才执行下面一条，将 COM5 换成真实端口：

```powershell
idf.py --preview -p COM5 flash monitor
```

下载/BOOT/RESET/退出 monitor 的完整操作见教程第 5 节；现在暂不执行这一条。

进入 `home>` 后逐条执行：

```text
home help
home status
```

**应看到：** 编译最后出现 Project build complete，烧录成功；LCD/串口可用。未连 STM32 时显示等待/断线、读数不可用是正常预期；不能出现静默生成的“真实室温”。如果看到 OFFLINE SIMULATION，先纠正构建配置。

**保存或回传：** Korvo 实际 COM 号、完整构建/烧录末尾、`home status` 文本、LCD 实际现象。成功后只给 Korvo 单板填结果。

### 2B. STM32 阶段 1

**前置条件：** 学习板供电、ST-Link 针脚与共地已核实；先不接传感器和驱动。按教程第 6 节及接线表接 SWD，不能把所有探针标“3.3V”的脚都当 VTref。

在工程根目录：

```powershell
cmake -S stm32 -B stm32/build-stage1 -G Ninja -DSTAGE=1
cmake --build stm32/build-stage1
```

在 STM32CubeProgrammer 选择 **ST-LINK / SWD**，先连接确认目标，再选择 `stm32/build-stage1/home_stm32.elf` 执行 Download、Verify、Reset；具体 GUI/可选 CLI 在教程第 6 节。不要把“编译出了 ELF”当成已经烧入 STM32。

**应看到：** 构建、连接目标、下载、校验分别成功。阶段 1 不提供环境读数，也不以某个板载灯亮判断程序成功。

**保存或回传：** STM32 构建末尾、CubeProgrammer 的目标识别/下载/校验文本、使用的 ELF 完整路径与 STAGE。

**进入下一步：** 两块板分别已下载并可运行；遇到供电、SWD 或端口问题先解决本关，不加入外设。

## 第 3 步：逐个建立真实闭环

### 3A. 先只做 USB 握手

**前置条件：** Korvo 为 USB 实机模式，STM32 为阶段 1，两板供电正确。断电后按接线表连接：

| CP210x | STM32 | 方向 |
| --- | --- | --- |
| TXD | PA10 / RX | 桥 → STM32 |
| RXD | PA9 / TX | STM32 → 桥 |
| GND | GND | 共地 |
| VCC/5V/3V3/DTR/RTS | 不接 | 不是本方案的板间供电或下载线 |

CP210x 直接插 Korvo **USB-A Host**，不经 Hub；模块不能同时插电脑。上电后在 Korvo 串口执行 `home status`。

**应看到：** USB 打开只代表识别到桥，随后还需 STM32 的握手和配置应答；状态最终应为 `stage=1`、`online=1`、`synced=1`。阶段 1 无数据，`stale=1`/读数不可用不能单独判为握手失败。拔 USB 后显示断开，重插后重新同步。预期与排错见教程第 7 节。

**保存或回传：** CP210x 打开日志、握手后完整 `home status`、拔出/重插后的状态与观察时间。没有握手成功先查模块身份、STM32 运行、TX/RX 交叉、电平和共地。

**进入下一关：** 正常、断开、重连均有真实记录；原配 LCD/触摸仍可用。

### 3B. 测试数据与 LED

按教程第 8 节单独构建/烧录 `STAGE=2`，LED 参数只用已确认的实际引脚/极性；未知时先核对板型。不要误烧 `build-stage1` 的 ELF，也不接真实负载。

**应看到：** 明确 TEST DATA 标签、固定 30℃/55%/50 lx；逐条 `home light on`、等成功 ACK，再 `home light off`，LED 实际动作与回报一致。初始 AUTO 和测试值可能让 LED 自动先亮，先看模式再判断。阶段 2 的风扇请求应拒绝。

**保存或回传：** LED 引脚依据、STAGE、测试来源标签、ON/OFF 请求/ACK 与 LED 实际现象。此关只能证明测试数据/LED 闭环。

**进入下一关：** LED 与双向应答已实际验收，不能把测试三元组记为真实采集。

### 3C. 只接真实传感器

按教程第 9 节断电接 SHT3x-DIS/BH1750 至 STM32 PB6/PB7，核对 3.3V 供电/上拉和 0x44/0x23 地址；仍不接负载。构建并烧录 `STAGE=3`。

**应看到：** `stage=3`、STM32 SENSORS/source=sensor，读数随真实环境变化。遮挡/恢复 BH1750 有趋势；按教程分别做单传感器断开/恢复，故障通道与仍有效通道能区分。光照/温度显示的小数位不代表已校准精度。

**保存或回传：** 两模块具体型号、供电/上拉依据、连续读数、遮光趋势、单通道故障/恢复状态。不能只说“出现了数字”。

**进入下一关：** 两类真实采集与故障恢复有实际记录，未用模拟值代替失败驱动。

### 3D. 最后接灯和风扇

按教程第 10 节核对驱动与负载规格、共地和独立低压电源，构建并烧录 `STAGE=4`。两路 GPIO 只接驱动 In；负载不从 MCU 或 Korvo Host 口供电。

**首次接通负载电源之前：** MCU/USB/传感器先正常运行；确认阶段 4 和已同步。依次发送 `home mode manual`、`home light off`、`home fan off`，**每条等成功 ACK、pending=0 再发下一条**，最后确认 MANUAL 与两路 OFF，才给独立负载电源上电。默认初始化 AUTO，同步后可能自动动作，不能省掉这个顺序。

先逐个手动开关，再按教程演示自动阈值与滞回。改阈值后等同步完成再发 `home mode auto`；手动开关会切回 MANUAL。无合适环境变化时，改阈值演示要明确记录为改阈值，不能写成真实升温实验。

**保存或回传：** 驱动/负载/供电规格、四阈值、模式、请求 ID/ACK/输出回报，另记实际灯亮灭和风扇旋转/停止。ON 回报没有转速或电流反馈，不能证明风扇真的在转。

**进入下一步：** 真实“采集→显示→操作→执行→回报”已有记录，且已清楚区分软件回报与物理动作。

## 第 4 步：保存、异常、MQTT 和手机

先做教程第 11 节：串口改阈值后等待 `synced=1`、`pending=0`，再单独 `home save`，确认 NVS 保存结果。分别复位 STM32 和 Korvo 检查恢复与重新同步，再按 [ACCEPTANCE](ACCEPTANCE.md) 验证 USB 失联、数据过期、传感器故障；未保存与已保存参数分别记录。

随后才进入教程第 12 节及 [NETWORK](NETWORK.md)：

| 关口 | 前置与最少操作 | 应看到 | 保存或回传的文字信息 |
| --- | --- | --- | --- |
| Korvo 联网 | 按文档启动 PC Mosquitto；menuconfig 填本人 Wi-Fi、API token、设备 ID、Broker 地址/凭据，重新构建烧录 | LCD/`net status` 有真实内网 IP；网络状态符合实际 | IP、脱敏 net status、失败原因/日志；不回传密码/token |
| MQTT 订阅 | 在 PC 使用对应账号订阅本设备 Topic | 每秒真实 source=sensor 状态；availability 仅说明 Korvo↔Broker | Topic、脱敏 JSON、Broker 停止/恢复前后状态 |
| 微信手机 | 自己的 AppID/开发权限；手机与 Korvo 同网段，输入 Korvo IP 和同一 token | 真机页面显示真实来源；单次请求等对应 ACK，再另记负载动作 | 手机系统/微信环境、实际页面状态、请求 ID/结果、真实动作记录 |
| 网络异常 | 按已通过的基础闭环逐项测试，不同时制造多种断线 | Wi-Fi/Broker/手机离线不停止 USB 心跳；本地有效自动规则继续 | 分清哪条链路断开、各端状态与恢复步骤 |

不要上传含密码/token/AppSecret 的截图或终端历史。**退出小程序、断 Wi-Fi 或停止 Broker 不等同于拔掉 Korvo↔STM32 USB**，也不会自动清除已有手动输出；手动约 5 秒关闭针对两板失联。

**进入下一步：** 保存/重连、网络上传和手机真机控制均有各自证据；电脑模拟器可用不能填手机真机 PASS。网络不通时先保留本地闭环，按层排错，不加入云平台或另写一套控制逻辑。
